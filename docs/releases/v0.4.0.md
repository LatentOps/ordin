# v0.4.0 release preparation

This is the release specification and migration record for the v0.4 line.
It is not an announcement that a tag or public release has been published.
Final publication remains gated on the exact tested source, the packaged pilot
window and explicit operator acceptance. Candidate verification cannot create
or replace an immutable release.

## Changes from v0.3

Ordin adds Cursor and pinned Hermes native hook contracts; strict JSON
boolean/number equality; bounded scanner-process cleanup; and fresh executable
discovery that preserves stdlib PATH order without repeated absent-directory
probes. Existing supported core review and v1 interchange behavior remains
covered by the unchanged v0.3 compatibility inventory.

The opt-in Swarm layer adds original host identity, delegation, causal source
flow, scoped budgets, durable coordination, retained human approval and owned
outcomes. Its managed MCP host exposes bounded authenticated tools, exact
approved writes, pinned fetches, fixed tests and explicit shutdown/restart.
Supported Linux protected launch confines a fresh child with original kernel
and cleanup evidence. Ordinary hook/callback/MCP interception is a separate
boundary and does not confine a client's other privileges.

Ordin Runtime and Ordin Security use Ordin-owned product names. Official client
identifiers, upstream ABI/wire identifiers, historical evidence and required
licenses retain their meanings. Optional Runtime v2 request constraints remain
scoped to qualified backend/prover behavior; unknown traffic does not turn into
a broad permission.

The [v0.4 inventory](../../data/public-surface-0.4.json) classifies the current
API, entry-point and schema surfaces. New opt-in Swarm, Runtime, Assurance,
security analysis and decision-model interfaces remain experimental. Existing
internal database/worker layouts are not promoted into compatibility contracts.

## Artifacts and migration

The planned verified bundle contains wheel/source pairs for `ordin` and
`ordin-swarm` 0.4.0 plus independently versioned `ordin-runtime`, `ordin-security`
and `ordin-decision-models` 0.1.0. Its manifest binds every artifact to the tested
source; checksums, the SBOM, license notices and hosted workflow attestation have
their own verification steps. Base packages do not provision optional SDKs or
native tooling. Follow the [artifact quickstart](../quickstart-0.4.md) and
[upgrade/rollback policy](../public-compatibility-0.4.md).

## Qualification boundaries

The maintained core platform matrix is Linux/Python 3.10–3.13 and macOS 15 with
Python 3.13. Windows portable/package/protocol fixtures establish only their
tested paths, not Windows native shell semantics or kernel protection. Owned
process enforcement requires the supported Linux x86-64 setup. Fourteen named
installed positives run on the required Linux Python 3.10/3.13 lanes; unsupported
platform skips cannot substitute for actual protected execution.

Pinned LangGraph asynchronous callbacks are interception; native async
broker/coordinator calls remain unsupported. AutoGen is legacy/archived.
CrewAI remains quarantined, including externally installed matching SDKs.
Unwrapped tools, preexisting processes, raw backing stores and direct sockets
remain explicit coverage gaps. Finite fixture results do not measure arbitrary
model behavior, universal taint tracking or all-agent safety.

Use [exact candidate acceptance](../release-candidate-gate.md) and the
[packaged pilot procedure](../release-pilot-0.4.md). Reports must record actual
elapsed duration, artifacts, counts, skipped scope and retained outcomes.
Short engineering runs do not complete a multi-day pilot. No pilot completion
date, public publication date or blanket production approval is asserted here.
